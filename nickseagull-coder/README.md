# Coder on Umbrel (package only)

Coder v2.36.7 and PostgreSQL 17.6 are pinned to multi-architecture image-index digests. The app is **not installed** by this repository. Its web UI is behind Umbrel's app proxy on port 4584. Coder accounts are created in Coder's first-run web setup; Umbrel's password is not a Coder password. The `/api/*` and `/derp/*` proxy exceptions allow CLI, workspace agents and DERP/WebSocket traffic to reach Coder without Umbrel browser cookies; **Coder's API authentication and DERP cryptographic identity are the boundary**. The first-account creation endpoint is reachable on `/api/*` before initialization: create the first account promptly on a trusted LAN before considering broader access. Do not expose this instance to untrusted networks based solely on the Umbrel proxy.

The PostgreSQL database and `/home/coder` persist under the Umbrel-movable `data/` root. The per-install PostgreSQL password derives from Umbrel's seed; the database is not host-published. There is one built-in provisioner (no external daemon or Premium dependency). That daemon executes Terraform templates in the Coder server container, so a template maintainer can access the mounted SSH identity and database connection environment. Restrict template authors, not just workspace users. No Docker socket is mounted; this app alone cannot create Docker workspaces.

## Before a future two-host template

1. Choose a stable `CODER_ACCESS_URL` that Umbrel, corthan, clients and *both hosts' workspace agents* can resolve and reach. The initial `http://<DEVICE_DOMAIN_NAME>:4584` is a local-network convenience, not a guarantee that Mac Docker VM containers can resolve `.local`; override it in Umbrel app Settings if needed. Prefer HTTPS with a certificate all clients trust. The app proxy must support WebSockets. Verify first-run account creation and agent callbacks **through the chosen URL**.
2. Create a dedicated SSH identity with only the Docker-host privileges explicitly approved for the two workers. Stage the private key and verified/pinned `known_hosts` in the installed app's `${APP_DATA_DIR}/data/ssh` directory *outside Git* (under the relocated data root if storage was moved). The directory is read-only inside Coder at `/home/coder/.ssh`. Use directory mode `0700` and private-key mode `0600`, readable by the Coder image's `coder` user; confirm ownership/UID on the running image. Never paste or commit the key. Never enable insecure host-key checking, agent forwarding or password SSH. Stage the identity only when the hosts and template are approved.
3. Explicitly approve and verify a Docker-over-SSH endpoint on the Umbrel host and one on corthan's Docker Desktop Linux VM. Pin both host keys; establish that Docker access is effectively root on each host and isolate it from unrelated host data. A future template should use a **fixed worker-ID allowlist** mapping to these SSH endpoints, not user-supplied URLs/keys, and pin the chosen worker for workspace lifetime. Do not assume macOS host SSH reaches the Docker Desktop daemon. Keep the template architecture-aware: Umbrel is x86_64, corthan's Docker engine is linux/arm64.
4. Back up `data/postgres` and `data/coder` consistently (stop the app or use a database-aware backup). A directory copy of live PostgreSQL is not a proven consistent backup. Test restore separately; do not mistake workspaces' Docker-local volumes for Coder's database state.
