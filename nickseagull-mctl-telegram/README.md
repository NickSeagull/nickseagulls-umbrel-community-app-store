# mctl Telegram on Umbrel

This package replaces the mistakenly selected `nguyenvanduocit/telegram-mcp` app; its source is [mctlhq/mctl-telegram](https://github.com/mctlhq/mctl-telegram/tree/47431f39eb153f99f6e7217ea2246cbb562cc623), Apache-2.0, tag `0.79.2`. The image workflow checks out that exact commit, runs upstream tests and publishes linux/amd64 + linux/arm64; Compose pins the anonymously verified OCI index digest.

## First-run prerequisites (do not paste credentials in chat)

1. Install the Umbrel app **unconfigured**. Its `server` process refuses to start until the owner and Telegram credentials are set; the internal Postgres service may run. Do not interpret an installed tile or a running database as Telegram access. Nick chose the tailnet-only `https://telegram-mcp.p.egregore.io` origin (preconfigured as `PUBLIC_BASE_URL`); configure a trusted HTTPS reverse proxy to this app's internal `server:8080` only after the private settings are complete. No public host port is exposed by this package.
2. Register a Telegram API application at [my.telegram.org/apps](https://my.telegram.org/apps). In [BotFather's Login Widget settings](https://core.telegram.org/bots/telegram-login), register the chosen origin and `https://telegram-mcp.p.egregore.io/oauth/telegram/callback`, then obtain the OIDC client ID and secret. The login bot is an identity provider, not a Telegram message-reading bot.
3. In Umbrel, open the **mctl Telegram** app's **Settings → Environment variables → Suggested by this app**. Set `TG_API_ID`, `TG_API_HASH`, `TELEGRAM_OIDC_CLIENT_ID`, `TELEGRAM_OIDC_CLIENT_SECRET`, and `TG_LOGIN_CLIENTS` (Nick's numeric Telegram user ID) for the `server` service; verify `PUBLIC_BASE_URL` is the chosen origin. Do not turn on auto-approval. Use Umbrel's owner-only UI, not chat, screenshots or Git. Umbrel displays these as ordinary text fields and stores them in app settings/generated Compose; it is not a masked secret vault. Apply and restart; the process must remain fail-closed while any credential is missing.
4. Verify app details/readiness, protected-resource discovery, OAuth callback and session persistence across a restart. Distinct Umbrel-derived keys sign JWTs, encrypt session material, and authenticate the local database. Postgres state lives under Umbrel's movable app-data root; back up the database directory and the Umbrel device seed used to derive the encryption and database keys. PostgreSQL preserves dynamic OAuth registrations across restarts; active in-progress flows may still need to restart after an update.
5. Connect Hermes through `auth: oauth` to `https://telegram-mcp.p.egregore.io/mcp`. Complete Telegram OIDC and then the separate MTProto phone/code/2FA browser wizard privately. The wizard defaults to **Read + send**—select **Read only**. Validate four read tools (`list_dialogs`, `get_unread_messages`, `get_messages`, `search_messages`) and verify that write tools are absent. The server's read-only filter includes other read-annotated tools too; Hermes should set `tools.include` to these four as a second filter.

Hermes dashboard OAuth uses the configured `oauth.redirect_uri` of `https://telegram-mcp.p.egregore.io/api/mcp/oauth/callback/telegram`: its Umbrel HTTP tile callback is not accepted by the server's redirect policy. NPM proxy host for the same private HTTPS hostname forwards **only** `/api/mcp/oauth/callback/telegram` to `http://hermes-agent_web_1:18789`; all other paths still go to the mctl server. This package allows that one byte-exact HTTPS callback for dynamic client registration via `OAUTH_DCR_REDIRECT_URIS`. Keep the callback URL, proxy location, and App Settings override in sync; do not allowlist the entire host or proxy the unauthenticated Hermes dashboard. The callback validates state and accepts an authorization code only for an active flow. Verify a callback request without state returns `404 OAuth flow expired` and `/mcp` still returns 401.

## Internal HTTPS route

The `tls_route` service gives `telegram-mcp.p.egregore.io` a **Docker-network-only** DNS alias on Umbrel's shared network. It passes raw TCP/TLS on port 443 to the existing `nginx-proxy-manager_web_1:443`; NPM retains certificate, canonical Host/SNI and OAuth routing. The HAProxy config is stored under `hooks/` so Umbrel updates copy it. Docker's embedded DNS resolver refreshes the NPM container address after recreation. No host port, new certificate, TLS bypass, or NPM restart is required. Only the mctl app is updated, so its server may briefly restart; encrypted user sessions and OAuth registrations live in persistent Postgres data.

Before update, check that no other shared-network container owns the hostname alias. After update, verify Docker DNS inside Hermes resolves the alias to `tls_route`, a normal `curl https://telegram-mcp.p.egregore.io/healthz` validates TLS and returns 200, and unauthenticated `/mcp` returns 401 with the canonical metadata URL. If NPM is down the route fails closed; do not route directly to the unencrypted backend or disable certificate checks.

## Security contract

- Compose explicitly sets `AUTH_MODE=local-jwt`, `AUTH_REQUIRED=true`, `MCP_TOOL_FILTER=read-only` and `ALLOW_SEND=false`. Do not replace this with local-dev auth or a static bearer shared in chat. The server-side read-only filter suppresses all write tools, including pin/delete/admin actions; the send gate independently prevents real message sends.
- Umbrel `app_proxy` retains its login gate for the local tile. A separately configured HTTPS proxy to the canonical hostname must be reviewed as public-facing; the upstream OAuth server authenticates `/mcp` and account pages. TLS/hostname, Telegram login bot and end-to-end Hermes OAuth compatibility remain deployment gates, not assumed properties of this package.
- No credential file is required. Blank app-setting variables keep the server unconfigured; never disable `AUTH_REQUIRED`, change `AUTH_MODE` to `none`, or enable sends to make first boot look healthy. Umbrel persists the owner-entered values as app settings and recreates the server on Apply and restart.

The source, image and deployment have not been connected to a Telegram account by CI; do not claim chat access before a real read-only MCP call succeeds.
